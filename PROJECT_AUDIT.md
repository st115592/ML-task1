# Краткая памятка проекта и научного аудита

**Исправления после проверки:** внутренняя и финальная настройка унифицированы
на RepeatedKFold(5×3), seed=142; внешняя CV и зависимые результаты пересчитаны.
Нормировки отклоняют NaN, ±inf, ноль и отрицательные значения. Добавлены
тесты согласованности сохранённого выбора и изоляции test-целей на уровне
полного эксперимента (с сокращёнными сетками/повторами только в тесте).

**Проект:** ML in Mechanics, «Линейная модель переходного процесса
сервопривода», репозиторий st115592/ML-task1. Данные — 167 строк UCI Servo.

**Структура:** исходные данные и описание в `data/raw/`; гипотезы и протокол
в `protocol.md`; модели и конвейер в `servo_model.py`; весь расчёт в
`run_analysis.py`; тесты в `test_servo.py`; таблицы, модель, bootstrap и
графики в `results/`; полный научный отчёт в `REPORT.md`.

**Основные замечания аудита:**

1. Единицы усилений и отклика не указаны источником. Секунды, инерции и
   передаточные числа не выдумываются; нормировки заданы явно. Историческое
   описание только предположительно называет отклик временем нарастания.
2. Категории A–E не являются числами с порядком. One-hot, полиномы и
   стандартизация обучаются в Pipeline внутри fold.
3. Данные малы: повторная вложенная CV и закрытый test; степень 3 исключена.
   Внешняя оценка всей процедуры выбора отделена от оценок семейств.
4. Модель log(y) после exp не линейна по коэффициентам в исходной шкале.
   Она приведена для сравнения; итоговая модель выбирается только среди raw.
5. Корреляция p,p²,pv делает отдельные коэффициенты неустойчивыми.
   Bootstrap с фиксированным базисом сравнивается с МНК на том же базисе;
   интервалы не учитывают всю неопределённость выбора модели.
6. Остатки проверяются по OOF, включая карту режимов. Перенос на pgain=3
   испытывается моделью, не видевшей этот режим; это экстраполяция по усилению.
   Малые тестовые подгруппы не позволяют причинных или универсальных выводов.
7. Линейная аппроксимация не гарантирует положительности и устойчивости
   реального привода. Отрицательные прогнозы не обрезаются. Наблюдения —
   историческая симуляция, а не новые экспериментальные измерения.

**Собственный проект:** небольшой Python-пакет без установки и CLI для
обучения, проверки и прогноза времени нарастания. Он сохраняет обученную
линейную модель и позволяет подать новую конфигурацию motor/screw/pgain/vgain.
Весь код на Python, параметры обучения и нормировки документированы.

**Запуск:** создать `.venv`, установить `requirements.txt`, выполнить
`python run_analysis.py`, затем
`python predict.py --motor A --screw A --pgain 4 --vgain 2`.
Использовать Python из `.venv\Scripts\python`; подробные команды — в README.
Проверки: `python -m pytest -q`, `python -m black --check *.py`,
`python -m flake8 . --exclude .venv`.
